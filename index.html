3. Replace the earlier local installation

If you installed the original localhost version, its registered manifest must be replaced. Merely publishing this website does not update the mailbox registration.

Using the working PowerShell route: in your connected Exchange Online PowerShell session, run Install-Hosted.ps1 from the extracted package. It asks for the target mailbox and the manifest you just downloaded. It checks the website before asking to replace the old Message Notes registration, then installs and enables this version only for that mailbox.

Using the browser: sign in as the intended mailbox user, then open Outlook's add-in installation dialog. In My add-ins > Custom Addins, remove the earlier Message Notes entry if present. Choose Add a custom add-in > Add from File and select the downloaded Message-Notes-GitHub.xml. Do not upload manifest.template.xml or the ZIP.

The ID and note property name are unchanged. Preserve a copy of any important notes before changing installations. Organization-managed installations must be updated by the administrator rather than removed here.

4. Open the sidebar

Refresh Outlook on the web. Open a normal received message in your own mailbox, then choose Apps > Message Notes on that message. Open new Outlook with the same mailbox, fully close and reopen it if necessary, then look on a received message there. Use Outlook's pin icon to keep the sidebar open.

Save a non-sensitive test note, select another message, return, and check the note. Then reopen that same email in the other Outlook client. Confirm persistence before using important notes.

The current build is a message-reading add-in. It is not a compose-window app, standalone navigation app, or a delegated/shared-mailbox-enabled build. Start with an ordinary unencrypted message in the mailbox where you installed it.

Data and hosting

The website contains only the program files. The current note code saves with Outlook custom properties on the selected message, not to GitHub, browser local storage, or a notes database. GitHub still receives ordinary website requests. Public site visitors cannot retrieve mailbox notes simply by opening this page.

GitHub Pages sites are generally public, including sites from private repositories unless a separately supported access-control feature is configured. Never publish messages, note exports, passwords, tokens, certificates, or tenant exports. Protect repository write access: changed add-in JavaScript runs with the add-in's permissions when users open it.
